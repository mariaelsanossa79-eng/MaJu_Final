Documentación del Proyecto MaJu — Data Lake & BI

Este documento describe la arquitectura de datos, el pipeline ETL y el dashboard de inteligencia de negocio desarrollados para MaJu Jabones y Velas Artesanales como proyecto académico de la asignatura Arquitectura de Datos — Ing. Fernando Benavides · Unicervantes 2024.

1. Descripción del negocio

MaJu Jabones y Velas Artesanales es un emprendimiento colombiano de productos artesanales fundado y operado por Mae Nossa. La empresa comercializa jabones naturales y velas decorativas elaboradas de manera artesanal, distribuyéndolos principalmente a través de canales digitales (WhatsApp, Instagram, TikTok, Facebook) y ferias artesanales. Sus clientes se encuentran en múltiples ciudades del país.

La implementación de un Data Lake permite a MaJu centralizar sus datos de ventas dispersos en distintos canales, generar analítica de negocio en tiempo cuasi-real y tomar decisiones basadas en evidencia para escalar el emprendimiento.

2. Arquitectura del Data Lake — Patrón Medallion

El pipeline implementa la arquitectura Medallion (Bronze → Silver → Gold), reconocida en la industria por su capacidad de garantizar calidad progresiva de datos desde la ingesta cruda hasta la capa analítica lista para consumo.

🟫 Capa Bronze — Ingesta cruda · MongoDB Atlas · Colecciones sin transformar
↓ limpieza · validación · deduplicación
⬜ Capa Silver — Datos limpios · tipos normalizados · llaves estandarizadas
↓ agregaciones · KPIs calculados · joins analíticos
🟡 Capa Gold — Datos listos para BI · modelos dimensionales · vistas SQL

La capa Bronze almacena los registros tal como llegan de cada fuente (exportaciones de WhatsApp, registros manuales, datos de feria). La capa Silver aplica reglas de calidad: eliminación de nulos críticos, normalización de nombres de ciudad y producto, conversión de tipos de fecha. La capa Gold expone vistas denormalizadas optimizadas para consulta analítica y alimentación del dashboard.

3. Modelo de datos — Esquema estrella (Data Warehouse)

El modelo dimensional implementado sigue un esquema estrella con una tabla de hechos central y cuatro tablas de dimensión:

  • hecho_ventas — tabla de hechos: id_venta, fecha, id_producto, id_cliente, id_canal, id_ciudad, cantidad, precio_unitario, total_cop, descuento, metodo_pago
  • dim_producto — SKU, nombre, categoría (jabón/vela), aroma, presentación, costo_produccion, precio_lista
  • dim_cliente — id_cliente, nombre, ciudad, canal_adquisicion, fecha_primera_compra, segmento_rfm
  • dim_canal — id_canal, nombre (WhatsApp, Instagram, TikTok, Facebook, Feria, Referido)
  • dim_tiempo — fecha, año, mes, semana, dia_semana, es_temporada_alta
-- Vista Gold: ingresos mensuales por canal CREATE VIEW gold_ingresos_canal AS SELECT dt.año, dt.mes, dc.nombre AS canal, SUM(hv.total_cop) AS ingresos_cop, COUNT(hv.id_venta) AS num_ventas, AVG(hv.total_cop) AS ticket_promedio FROM hecho_ventas hv JOIN dim_tiempo dt ON hv.id_fecha = dt.id_fecha JOIN dim_canal dc ON hv.id_canal = dc.id_canal GROUP BY dt.año, dt.mes, dc.nombre;

4. Pipeline ETL

El proceso ETL se implementó en Python 3.10 con las bibliotecas pandas, pymongo y sqlalchemy. El flujo es el siguiente:

  • Extract: lectura de archivos CSV de ventas manuales, exportaciones de registros de WhatsApp y datos de ferias.
  • Transform: normalización de columnas, imputación de nulos, estandarización de nombres (ciudades, productos), cálculo de campos derivados (total_cop, margen_bruto).
  • Load: inserción en MongoDB Atlas (Bronze) y posterior volcado a MySQL 8 (Silver/Gold).
import pandas as pd from pymongo import MongoClient # Conexión Bronze (MongoDB Atlas) client = MongoClient("mongodb+srv://maju:***@cluster0.mongodb.net/") db = client["maju_datalake"] bronze = db["ventas_raw"] # Cargar CSV crudo → Bronze df = pd.read_csv("ventas_2024.csv") bronze.insert_many(df.to_dict("records")) # Transformación → Silver df["fecha"] = pd.to_datetime(df["fecha"], dayfirst=True) df["ciudad"] = df["ciudad"].str.strip().str.title() df["total_cop"] = df["cantidad"] * df["precio_unitario"] df.dropna(subset=["id_cliente","id_producto"], inplace=True) # Cargar Silver → MySQL from sqlalchemy import create_engine engine = create_engine("mysql+pymysql://root:***@localhost/maju_dw") df.to_sql("silver_ventas", engine, if_exists="replace", index=False)

5. Agente conversacional (IA)

El proyecto integra un agente conversacional basado en Claude (Anthropic) que responde preguntas en lenguaje natural sobre los datos de MaJu. El agente accede a la capa Gold para traducir preguntas como "¿Cuál fue el producto más vendido en marzo?" a consultas SQL y devolver respuestas comprensibles al usuario no técnico.

  • Tecnología: API de Anthropic · modelo claude-sonnet-4
  • Contexto de sistema: esquema de la base de datos Gold + reglas de negocio MaJu
  • Interfaz: widget embebido en el dashboard (pestaña Resumen)

6. Dashboard de inteligencia de negocio

El dashboard presenta cuatro vistas analíticas:

  • Resumen — KPIs globales, ingresos mensuales, distribución por canal y por ciudad.
  • Ventas — análisis por categoría, acumulado, detalle de transacciones y métodos de pago.
  • Productos — rendimiento por SKU, margen bruto y matriz ingreso vs. rotación.
  • Clientes — segmentación RFM, distribución geográfica y top clientes por valor.

El dashboard fue desarrollado en HTML5/CSS3/JavaScript puro con Chart.js, sin dependencia de frameworks externos, lo que facilita su despliegue en cualquier entorno.
